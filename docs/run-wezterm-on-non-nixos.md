# Running WezTerm on non-NixOS (Nix + NVIDIA)

> [!NOTE]
> This document was generated by Claude Code (Anthropic) based on debugging sessions and may contain inaccuracies.

When installing WezTerm via Nix home-manager on a non-NixOS system, it fails to launch due to missing OpenGL/EGL libraries. This document covers the root causes and the solution.

## Environment

| Item | Value |
|---|---|
| OS | Ubuntu 24.04 (non-NixOS) |
| GPU | Intel Iris Xe (display output) + NVIDIA RTX 4050 (offload) |
| NVIDIA driver | 595.58.03 (proprietary) |
| Nix | flakes + home-manager (nixpkgs-unstable) |
| Session | X11 (`XDG_SESSION_TYPE=x11`) |

## Background

### Nix dynamic linker behavior

Nix packages use `/nix/store/...-glibc/lib/ld-linux-x86-64.so.2` as their ELF interpreter. This Nix `ld-linux`:

- Does **not** read `/etc/ld.so.cache` (the system library cache)
- Does **not** search system paths like `/usr/lib/x86_64-linux-gnu/`
- Only searches `DT_RUNPATH` and `LD_LIBRARY_PATH`

In other words, Nix binaries cannot see any libraries installed on the host system.

### libglvnd multi-vendor dispatch

libglvnd is a vendor-neutral GL/EGL dispatch layer. It reads JSON files specified by `__EGL_VENDOR_LIBRARY_FILENAMES` and loads each vendor's EGL implementation:

```json
// 10_nvidia.json
{ "file_format_version": "1.0.0", "ICD": { "library_path": "libEGL_nvidia.so.0" } }

// 50_mesa.json
{ "file_format_version": "1.0.0", "ICD": { "library_path": "/nix/store/.../libEGL_mesa.so.0" } }
```

When `eglGetDisplay` is called, libglvnd tries each vendor in order and automatically selects the one that matches the display.

### NVIDIA EGL external platform mechanism

NVIDIA's EGL driver (`libEGL_nvidia.so.0`) reads JSON configs from `/usr/share/egl/egl_external_platform.d/` at startup and `dlopen`s platform libraries for XCB, Xlib, GBM, Wayland, etc.:

```json
// 20_nvidia_xcb.json
{ "ICD": { "library_path": "libnvidia-egl-xcb.so.1" } }
```

These platform libraries are installed by Ubuntu packages (`libnvidia-gl-595`, etc.) into `/usr/lib/x86_64-linux-gnu/`. Since Nix's `ld-linux` does not search that path, they are normally not found.

## Errors encountered

### 1. SIGSEGV (initial state)

Without any GL libraries in the search path, Nix's WezTerm crashes immediately with SIGSEGV because it cannot find any OpenGL/EGL implementation.

### 2. `eglGetDisplay: BAD_ALLOC` (NVIDIA EGL only)

After adding NVIDIA core libraries to `LD_LIBRARY_PATH` and setting `__EGL_VENDOR_LIBRARY_FILENAMES` to NVIDIA's JSON only, `eglGetDisplay` fails because this is a hybrid GPU setup where Intel handles display output. NVIDIA EGL cannot create a display on an Intel-driven screen:

```
Failed to create window: with_egl_lib failed: egl GetDisplay: BAD_ALLOC
```

## Solution

### Architecture overview

```
LD_LIBRARY_PATH =
  /nix/store/...-libglvnd/lib         <- vendor-neutral dispatcher
  /nix/store/...-nvidia-gl-libs/lib   <- NVIDIA core GL/EGL libraries
  /nix/store/...-mesa/lib             <- Mesa EGL (for Intel)
  ~/.local/lib/nvidia-egl-platforms/  <- NVIDIA EGL external platforms (copied from system)

__EGL_VENDOR_LIBRARY_FILENAMES =
  10_nvidia.json : 50_mesa.json       <- both vendors registered -> auto-selected
```

### Step 1: Extract NVIDIA core GL libraries

Extract core GL/EGL libraries from NVIDIA's `.run` installer into the Nix store. This includes `libEGL_nvidia.so.0`, `libGLX_nvidia.so.0`, `libnvidia-glcore`, `libnvidia-eglcore`, and `libnvidia-glsi`. These are NVIDIA-specific and cannot be replaced by Mesa.

### Step 2: Copy EGL external platform libraries

Copy 5 platform libraries from the system into `~/.local/lib/nvidia-egl-platforms/`:

- `libnvidia-egl-xcb.so.1` (X11/XCB)
- `libnvidia-egl-xlib.so.1` (X11/Xlib)
- `libnvidia-egl-gbm.so.1` (GBM)
- `libnvidia-egl-wayland.so.1` (Wayland)
- `libnvidia-egl-wayland2.so.1` (Wayland v2)

This is done at `home-manager switch` time via an activation script, since the Nix build sandbox cannot access system files.

**Important**: No transitive dependencies (`libdrm`, `libgbm`, `libxcb`, etc.) need to be copied. When Mesa EGL is loaded earlier in the process, its RUNPATH pulls all of these from the Nix store. The dynamic linker reuses already-loaded libraries by SONAME matching, so the platform libraries' dependencies are resolved automatically.

### Step 3: Enable vendor auto-selection

Set `__EGL_VENDOR_LIBRARY_FILENAMES` to include both NVIDIA and Mesa vendor JSONs. libglvnd then automatically selects the appropriate vendor based on the display:

```
Intel display (X11) -> Mesa EGL selected
NVIDIA display      -> NVIDIA EGL selected
```

## Implementation

The final `wezterm.nix`:

```nix
{ config, pkgs, lib, ... }:

let
  nvidiaVersion = "595.58.03";

  # NVIDIA core GL libraries (extracted from .run installer)
  nvidiaLibs = pkgs.stdenv.mkDerivation {
    pname = "nvidia-gl-libs";
    version = nvidiaVersion;
    src = pkgs.fetchurl {
      url = "https://download.nvidia.com/XFree86/Linux-x86_64/${nvidiaVersion}/NVIDIA-Linux-x86_64-${nvidiaVersion}.run";
      sha256 = "1y99b0h3cv8panjsz4icf052nf83h7p2l9qlaymw8ckrgfb4y3cc";
    };
    nativeBuildInputs = [ pkgs.zstd ];
    phases = [ "installPhase" ];
    installPhase = ''
      mkdir -p $out/lib $out/share/glvnd/egl_vendor.d
      sh $src --extract-only --target nvidia
      cd nvidia

      for lib in libEGL_nvidia libGLX_nvidia libnvidia-glcore libnvidia-eglcore libnvidia-glsi; do
        cp ''${lib}.so.${nvidiaVersion} $out/lib/ 2>/dev/null || true
      done

      ln -sf libEGL_nvidia.so.${nvidiaVersion} $out/lib/libEGL_nvidia.so.0
      ln -sf libGLX_nvidia.so.${nvidiaVersion} $out/lib/libGLX_nvidia.so.0

      cp 10_nvidia.json $out/share/glvnd/egl_vendor.d/
    '';
  };

  eglPlatformDir = "/home/oyatomo/.local/lib/nvidia-egl-platforms";

  eglPlatformLibs = [
    "libnvidia-egl-xcb.so.1"
    "libnvidia-egl-xlib.so.1"
    "libnvidia-egl-gbm.so.1"
    "libnvidia-egl-wayland.so.1"
    "libnvidia-egl-wayland2.so.1"
  ];

  # WezTerm wrapper (injects library paths and vendor config)
  wezterm-with-gl = pkgs.symlinkJoin {
    name = "wezterm";
    paths = [ pkgs.wezterm ];
    nativeBuildInputs = [ pkgs.makeWrapper ];
    postBuild = ''
      for bin in wezterm wezterm-gui; do
        rm $out/bin/$bin
        makeWrapper ${pkgs.wezterm}/bin/$bin $out/bin/$bin \
          --prefix LD_LIBRARY_PATH : "${pkgs.lib.makeLibraryPath [ pkgs.libglvnd nvidiaLibs pkgs.mesa ]}:${eglPlatformDir}" \
          --set __EGL_VENDOR_LIBRARY_FILENAMES "${nvidiaLibs}/share/glvnd/egl_vendor.d/10_nvidia.json:${pkgs.mesa}/share/glvnd/egl_vendor.d/50_mesa.json"
      done
    '';
  };
in
{
  programs.wezterm = {
    enable = true;
    package = wezterm-with-gl;
  };

  xdg.configFile."wezterm".source = ./../../../../wezterm;

  # At activation: copy EGL platform libraries from the system
  home.activation.setupNvidiaEglPlatforms = lib.hm.dag.entryAfter ["writeBoundary"] ''
    EGL_DIR="${eglPlatformDir}"
    mkdir -p "$EGL_DIR"

    # Clean up stale transitive deps from earlier versions
    find "$EGL_DIR" -maxdepth 1 -type f -name '*.so*' ! -name 'libnvidia-egl-*' -delete

    for lib in ${lib.concatStringsSep " " eglPlatformLibs}; do
      src="/usr/lib/x86_64-linux-gnu/$lib"
      if [ -f "$src" ] || [ -L "$src" ]; then
        cp -Lf "$src" "$EGL_DIR/$lib"
      fi
    done
  '';
}
```

## Failed approaches

### nixGL (incompatible with current nixpkgs)

[nixGL](https://github.com/NixOS/nixGL) is a community tool that provides GPU acceleration on non-NixOS. However, with current `nixpkgs-unstable`, the `kernel` argument was removed from `nvidia-x11/generic.nix`, causing a build failure:

```
error: function 'anonymous lambda' called with unexpected argument 'kernel'
```

Reported in [NixOS/nixGL#169](https://github.com/NixOS/nixGL/issues/169), unresolved at the time of writing.

### Adding `/usr/lib/x86_64-linux-gnu` to LD_LIBRARY_PATH (glibc conflict)

Adding the system library path directly to `LD_LIBRARY_PATH` causes a glibc version conflict. `LD_LIBRARY_PATH` takes precedence over `DT_RUNPATH`, so the system's `libc.so.6` (glibc 2.39) is found before the Nix one (glibc 2.42). Nix binaries requiring `GLIBC_2.42` then fail:

```
/lib/x86_64-linux-gnu/libc.so.6: version 'GLIBC_2.42' not found
```

### Forcing NVIDIA EGL only (fails on hybrid GPU)

Setting `__EGL_VENDOR_LIBRARY_FILENAMES` to NVIDIA's JSON only. On this hybrid GPU laptop, Intel handles display output. NVIDIA EGL cannot create a display on an Intel-driven screen, resulting in `BAD_ALLOC`. The fix required registering both Mesa (for Intel) and NVIDIA vendors and letting libglvnd auto-select.

### Copying transitive deps of EGL platform libraries (library conflict)

Copied the EGL platform libraries and all their transitive dependencies (`libdrm`, `libgbm`, `libxcb`, `libX11`, etc. -- 20 files total) into `~/.local/lib/nvidia-egl-platforms/` with `patchelf --set-rpath '$ORIGIN'` to make them self-contained.

This caused the system copies of `libdrm`, `libxcb`, `libX11` etc. to shadow the Nix versions via `LD_LIBRARY_PATH` precedence, breaking WezTerm's Nix dependencies and causing `BAD_ALLOC`.

A minimal test using `eglinfo` confirmed that only the 5 platform libraries (without transitive deps) are sufficient. Transitive deps are already provided by Mesa EGL's load chain from the Nix store and are reused via the dynamic linker's SONAME matching.

### Setting `prefer_egl = false` (no effect on X11)

Setting `prefer_egl = false` in `wezterm.lua`. WezTerm's X11 backend requires EGL and has no GLX fallback. This setting only affects the Wayland backend.

## Adapting to other environments

### NVIDIA-only (non-hybrid)

If the display is driven exclusively by NVIDIA, Mesa may not be needed. Try setting `__EGL_VENDOR_LIBRARY_FILENAMES` to NVIDIA's JSON only and removing `pkgs.mesa` from `LD_LIBRARY_PATH`.

### AMD/Intel-only (no NVIDIA)

Mesa alone should work. NVIDIA library extraction and EGL platform copying are unnecessary. Add `libglvnd` and `mesa` to `LD_LIBRARY_PATH`, and set `__EGL_VENDOR_LIBRARY_FILENAMES` to Mesa's JSON.

### Changing NVIDIA driver version

Update `nvidiaVersion` and `sha256`. Get the hash with:

```bash
nix-prefetch-url https://download.nvidia.com/XFree86/Linux-x86_64/<VERSION>/NVIDIA-Linux-x86_64-<VERSION>.run
```

### Applying to other GPU-bound applications

The same approach (`symlinkJoin` + `makeWrapper` + activation script) works for any Nix GUI application requiring GL/EGL. Applications like `alacritty`, `kitty`, or `firefox` may exhibit similar issues.
